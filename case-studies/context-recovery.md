# A fresh-session assistant distinguishes old notes from current instructions

**Evidence date:** 23 September 2026. **Maturity:** accepted bounded proof of concept.

An older handoff described unfinished work, while a later authoritative update recorded completion. An assistant that repeated the old summary could reopen completed tasks or mislead its user. I wanted continuity that could be tested, rather than assumed from the existence of saved notes.

I required defined responsibilities, usable handoffs and fresh-session checks. Agents implemented the retrieval integration and performed the test and independent audit. My contribution was operating direction and acceptance expectations, not model training or personal implementation of every control.

The fresh assistant received a specific recovery question, approved context and a procedure for reporting evidence and uncertainty. It made one permitted context query and received the complete handoff through a controlled interface. It recognised the difference between the dated snapshot and the later current-state update, reported the completed work and kept unmeasured service health unknown.

An independent reviewer checked the actual tool result, supplied handoff content, run attribution and response. The task was accepted. Six lifecycle records subsequently appeared in the dashboard's data projection; that was record visibility, not a separate test of the visual interface.

The agent interpreted dates and source precedence. The surrounding integration constrained retrieval and recorded the task and result. Structured requests and receipts used JSON; source notes used Markdown. Task utilities and test fixtures supported verification. The assistant did not independently inspect the original file, calculate its hash or test live service health. Historical instructions in a retrieved document did not become new execution authority.

**What this demonstrates:** one assistant used approved context to answer one recovery question accurately under review. The earlier gap in complete-handoff retrieval was closed for this test. This is relevant to adoption because users need to know which information an assistant used and what it still cannot establish.

**Limits:** this is not a finished company-wide memory service, unrestricted source access or evidence of sustained workforce adoption. Another manager run still reached stale conclusions despite reading its sources. The accepted result cannot be generalised to all agents or future tasks.

This sanitised account is based on dated task, audit and collection records reviewed for the evidence handoff. Private records and implementation details remain unpublished. No commercial outcomes or time savings are claimed.
